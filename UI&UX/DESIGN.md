# Hufu Wallet UI 设计规范

> 本文件是 Hufu HTML 高保真设计稿与后续 Flutter 页面设计的统一视觉约束。
> 规范基于当前 `hufu_app` 的主题、核心页面、通用组件和品牌素材提炼，并参考同级项目 DESIGN.md 的组织方式重新整理。
> 当历史页面存在多个近似值时，以本文定义的语义 Token 为准；禁止继续复制零散硬编码。

---

## 1. 产品与设计定位

- **产品名称**：Hufu Wallet
- **产品类型**：多链 Web3 钱包、资产管理、行情、DApp、社交与 AI 助手
- **目标设备**：iOS / Android 手机，竖屏优先
- **设计基准**：Flutter `390 × 844`；HTML 预览使用固定 `420px` 画布
- **当前主题**：浅色主题为正式视觉基线
- **设计语言**：清爽金融科技、品牌蓝、高信息密度、轻量卡片、克制装饰
- **品牌气质**：安全、可信、专业、开放、连接多链生态
- **界面语言**：跟随应用国际化配置，禁止使用 Lorem Ipsum

Hufu 不采用通用 Web3 产品常见的大面积暗色、霓虹和重玻璃拟态。现有视觉以白色为主背景，以蓝色建立品牌识别，通过链图标、资产卡片、数字排版和少量蓝绿渐变表达科技感。

---

## 2. 核心设计原则

1. **资产优先**：余额、币种、涨跌、地址和关键操作必须形成最清晰的信息层级。
2. **安全可信**：签名、授权、转账、导出密钥等高风险动作必须展示对象、网络、金额和风险说明，不用含糊文案。
3. **品牌克制**：品牌蓝只用于主操作、选中态和核心资产区域，避免整页高饱和铺色。
4. **金融可读**：金额与行情数字对齐稳定，涨跌不能只依赖颜色表达。
5. **跨链一致**：链色和币种色只作为局部识别，不覆盖 Hufu 的全局交互色。
6. **移动优先**：触控区域不小于 `44 × 44px`，底部操作避让安全区。
7. **轻量层次**：优先使用背景层级、细边框和留白区分模块，投影只用于悬浮或重点快捷入口。
8. **国际化友好**：布局必须容纳中英文长度差异，标题、地址和代币名称都要定义溢出策略。

| 语义 | Token | 色值 | 用途 |
| --- | --- | --- | --- |
| 品牌主色 | `brandPrimary` | `#3E78FF` | 主按钮、选中态、链接、焦点、资产主卡 |
| 品牌深色 | `brandDeep` | `#354180` | 深色品牌辅助、重要标签 |
| 品牌浅底 | `brandSoft` | `#F3F5FF` | 选中项背景、信息模块浅底 |
| 品牌提示底 | `brandInfoBg` | `#E8F2FF` | 公告、提示条、轻提示模块 |
| 品牌淡蓝 | `brandPale` | `#E0F3FF` | 装饰背景、弱强调 |
| 导航激活兼容色 | `navActiveLegacy` | `#1573FE` | 仅兼容现有底部导航；新稿优先使用 `brandPrimary` |

> 品牌色铁律：新设计以 `#3E78FF` 为唯一全局主色。链品牌色仅用于链图标、链标签或资产识别，不用于全局 CTA。

### 3.2 文字色

| 主文字兼容色 | `textPrimaryAlt` | `#11183C` | 兼容设置页和历史组件 |
| 次文字 | `textSecondary` | `#7B7D8C` | 描述、标签、辅助信息 |

正文文字与背景的对比度应达到 `4.5:1`。`textTertiary` 只用于辅助信息，不用于关键正文或按钮文字。

背景层级禁止混用：核心内容页保持白底；需要明显分组的设置页才使用 `#F5F6F7`；卡片始终以白色表面承载内容。

| 弱边框 | `borderSubtle` | `#EFF2F6` | 轻量容器、表格分隔 |
| 分割线 | `divider` | `#EAEDEE` | 列表项、区块边界 |

| 下跌 / 危险 | `danger` | `#E8506C` | 下跌、失败、危险操作 |
| 警告 | `warning` | `#F39911` | Gas、授权风险、待处理 |
| 提示强调 | `notice` | `#FF4C00` | 必须阅读的提示文字 |
| 信息 | `info` | `#3E78FF` | 普通状态说明、链接 |

涨跌状态必须同时展示 `+ / −`、箭头或文字，不能只靠红绿颜色区分。危险操作使用红色，但普通返回、取消操作保持中性色。

### 3.6 品牌渐变与装饰

- 核心资产主卡允许使用蓝色主面与青蓝柔光，基准来自现有 `home_bg.png`。
- 装饰只允许用于资产主卡、品牌欢迎页和 AI 重点入口，不用于普通表单或列表背景。
- 装饰线条使用低透明度白色曲线，基准来自 `card_bg.png` / `card_bg2.png`。
- 禁止大面积彩虹渐变、霓虹外发光和高透明玻璃卡片。

## 4. 字体与数字排版

### 4.1 字体家族

| 内容 | 字体 | 说明 |
| --- | --- | --- |
| 拉丁正文与标题 | `Manrope-Regular` / `Manrope-Bold` | Hufu 品牌正文与界面标题 |
| 金额、价格、百分比 | `DIN-Medium` / `DIN-Bold` | 金融数字，保证紧凑与对齐 |
| 中文及缺字回退 | 系统无衬线字体 | iOS PingFang SC / Android Noto Sans CJK |

不要在普通页面引入 Orbitron、衬线字体或其他强装饰字体。地址、哈希和公钥建议使用等宽字体回退，并允许中间省略。

### 4.2 字号层级

| 层级 | 字号 | 字重 | 建议行高 | 用途 |
| --- | --- | --- | --- | --- |
| Amount XL | `24px` | 700 | `1.25` | 总资产、核心余额 |
| Title L | `20px` | 600 / 700 | `1.35` | 强调标题、结果页标题 |
| Page Title | `18px` | 500 / 600 | `1.4` | 页面标题、AppBar 标题 |
| Section Title | `16px` | 500 / 600 | `1.5` | 区块标题、列表主标题 |
| Body | `14px` | 400 / 500 | `1.55` | 正文、按钮、币种名称 |
| Body Small | `13px` | 400 | `1.5` | 搜索提示、次级说明 |
| Caption | `12px` | 400 / 500 | `1.5` | 时间、地址、行情辅助信息 |
| Micro | `10px` | 400 / 500 | `1.4` | 底部导航、角标；不得用于正文 |

### 4.3 金融数字规则

- 金额、价格、Gas、涨跌幅统一使用 DIN，使用 `tabular-nums` 等宽数字特性。
- 主金额最多两行；第一行是金额，第二行是法币折算或涨跌说明。
- 小数精度由业务决定，视觉上弱化超出主要精度的小数位，不随意截断真实数值。
- 正数涨幅显示 `+`，负数显示 `−`，零值使用中性色。
- 长地址采用 `0x1234…ABCD` 形式，复制按钮紧邻地址但保持独立点击区域。

## 5. 间距与布局网格

采用 `4px` 最小单位与 `8px` 主节奏。

| Token | 值 | 用途 |
| --- | --- | --- |
| `space-1` | `4px` | 图标与短标签、紧凑间隔 |
| `space-2` | `8px` | 控件内部小间距 |
| `space-3` | `12px` | 输入内边距、紧凑卡片 |
| `space-4` | `16px` | 标准卡片内边距、模块间距 |
| `space-5` | `20px` | 操作组、宽松行间距 |
| `space-6` | `24px` | 页面左右安全边距、区块间距 |
| `space-8` | `32px` | 大区块留白 |

布局规则：

- 新页面左右安全边距统一 `24px`。
- 钱包首页历史值 `25px` 可保留，但新稿不得同时混用 `24px` 与 `25px`。
- 普通卡片内边距 `16px`，高密度行情列表可使用 `12px`。
- 相邻卡片间距 `12px` 或 `16px`；大区块间距 `24px`。
- 列表行高至少 `48px`，推荐 `52–56px`。
- 所有可点击元素的实际命中区域至少 `44 × 44px`。

## 6. 圆角、边框与投影

### 6.1 圆角层级

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius-sm` | `8px` | 小按钮、图片、标签容器 |
| `radius-md` | `10px` | 输入框、普通按钮 |
| `radius-lg` | `12px` | 标准卡片、搜索框、弹窗内部组件 |
| `radius-xl` | `16px` | 公告条、大卡片、底部面板顶部 |
| `radius-2xl` | `20px` | 首页快捷操作卡 |
| `radius-hero` | `32px` | 钱包资产主卡 |
| `radius-pill` | `999px` | 胶囊标签、状态标记 |

禁止无语义地混用 `14px`、`15px`、`18px` 等近似值。圆形头像、币种图标和 FAB 使用 `50%`。

### 6.2 边框

- 输入框、搜索框和可选卡片使用 `1px` 边框。
- 聚焦态切换为品牌蓝，错误态切换为危险红。
- 普通内容卡片可在“浅灰背景 + 白色卡片”场景下省略边框。
- 不使用粗黑描边，不将 Comic 风格的重边框引入当前 Hufu 视觉。

### 6.3 投影

| 层级 | CSS 参考 | 用途 |
| --- | --- | --- |
| 无投影 | `none` | 列表、按钮、普通卡片 |
| 轻投影 | `0 4px 16px rgba(33, 100, 182, 0.08)` | 重点卡片 |
| 悬浮投影 | `0 8px 30px rgba(0, 0, 0, 0.06)` | 首页快捷入口、悬浮控件 |

投影不能代替边界和留白。禁止高不透明度黑色重投影。

## 7. 核心组件规范

### 7.1 顶部导航 AppBar

- 高度：`56px`，另加系统状态栏安全区。
- 背景：核心页面用白色；设置分组页可与 `groupedBackground` 一致。
- 标题：`18px`，Medium / SemiBold，颜色 `textPrimary`。
- 返回与操作图标：`24px`，点击区域至少 `44px`。
- 默认无投影；需要分隔时仅加 `1px` 弱分割线。
- 首页可使用左侧头像 / 入口与右侧钱包选择器，不强制居中标题。
- HTML 设计稿中使用 `position: sticky`，并放在画布滚动容器内部。

### 7.2 底部导航

- 高度：`56px + env(safe-area-inset-bottom)`。
- 背景：白色；顶部可使用 `1px` 极弱分割线。
- 图标：普通项 `23–24px`，AI 等特殊图标可为 `20px`，但视觉重量必须一致。
- 标签：`10–12px`；激活色 `brandPrimary`，未激活色 `textTertiary`。
- 每个导航项平分宽度，整个区域可点击。
- 固定导航必须锚定画布，不得贴到 PC 浏览器视口两侧。

### 7.3 钱包资产主卡

- 作为钱包页首要视觉，使用 `brandPrimary` 或蓝青品牌渐变。
- 圆角：`24–32px`，新稿统一采用 `32px`。
- 卡片内容顺序：钱包 / 网络 → 地址 → 总资产 → 法币折算 / 状态。
- 主金额使用 DIN Bold，白色；地址和辅助说明使用 `textOnBrandMuted`。
- 背景可使用白色低透明曲线装饰，但不得干扰文字。
- 复制、二维码、切换网络等图标必须具有独立 `44px` 点击区域。

### 7.4 快捷操作

- 适用于转账、收款、记录、扫一扫等高频动作。
- 高保真首页使用四列等宽的上图下文布局，不显示按钮底色；单项高度不低于 `72px`，图标容器 `44px`，文字 `14px`。
- 图标采用主题主蓝单层图标底，白色图形反显并保持统一线宽；文字位于图标下方并居中。
- `390px` 与 `420px` 画布均完整显示四项，不压缩触控区域。

### 7.5 按钮

#### 主按钮

- 高度：`48px`，宽度根据场景全宽或内容自适应。
- 背景：`brandPrimary`；文字：白色 `14px / 500–600`。
- 圆角：`10–12px`；无投影。
- 加载时保留按钮宽度，禁用重复点击。

#### 次按钮

- 白色或透明背景，`1px brandPrimary` 描边，品牌蓝文字。
- 与主按钮并排时主按钮视觉权重更高。

#### 危险按钮

- 使用 `danger`，必须搭配清晰动词，例如“删除钱包”“撤销授权”。
- 涉及私钥、助记词和资产不可逆操作时增加二次确认。

#### 文字按钮

- 最小点击区域 `44px`，不能只让文字字形本身可点击。
- 链接文字使用品牌蓝，不添加无必要的下划线。

### 7.6 输入框与搜索

- 标准高度 `48px`；多行输入按内容扩展。
- 圆角 `10–12px`，默认 `1px borderDefault`。
- 输入文字 `14–16px`，占位文字使用 `textTertiary`。
- 聚焦边框 `brandPrimary`，错误边框 `danger`，错误文案显示在字段下方。
- 搜索框可使用 `subtleBackground` 或白底描边，左侧图标 `20px`。
- 密码、私钥等敏感输入必须提供显隐控制，并防止误触复制或截屏泄露。

### 7.7 卡片与列表

- 标准卡片：白色、`12–16px` 圆角、`16px` 内边距。
- 行情列表：币种图标 `36–40px`，名称与代码左对齐，价格与涨跌右对齐。
- 设置列表：行高 `48–56px`，左图标 `24px`，右侧使用说明、开关或箭头。
- 分割线从文本内容起始位置对齐，避免穿过左侧图标。
- 可点击整行，不只让箭头可点击。

### 7.8 Tab 与筛选器

- 一级 Tab：`16px`，选中 `500–600`，未选中 `400`。
- 选中态使用主文字或品牌蓝，未选中使用次文字。
- 可使用品牌蓝短下划线或浅蓝胶囊背景，单页只选择一种模式。
- 行情正序 / 倒序等筛选必须同时显示图标和当前状态。

### 7.9 标签与链标识

- 高度 `24–28px`，左右内边距 `8–12px`，胶囊圆角。
- 网络标签可使用链品牌色浅底，但文字对比度必须达标。
- 状态标签使用语义色浅底 + 深色文字，不使用纯高饱和底色承载小字。

### 7.10 弹窗与底部面板

- 弹窗宽度不超过画布内容宽度减 `48px`，圆角 `16px`。
- 蒙层使用 `rgba(0, 0, 0, 0.54)`。
- 底部面板顶部圆角 `16px`，底部延伸至安全区。
- 动画使用 `150–250ms` 淡入或纵向位移。
- 交易确认内容按“网络 → 对方 → 资产 → 金额 → Gas → 风险”顺序展示。

### 7.11 空状态、加载与错误

- 空状态由统一插图 / 图标、标题、说明和可选 CTA 组成。
- 加载列表使用骨架屏并预留最终内容高度，避免跳动。
- 页面级加载可使用品牌蓝加载指示器。
- 错误信息就近展示；需要重试时提供明确按钮。
- 成功、警告和错误不能只显示 Toast，重要资产操作必须有可追溯结果页。

## 8. 页面模式

### 8.1 钱包首页

结构顺序：

1. 顶部账户入口与钱包切换
2. 资产主卡
3. 转账 / 收款 / 记录 / 扫一扫快捷操作
4. 公告或安全提示条
5. 资产 / NFT 等内容 Tab
6. 币种或资产列表

首页只保留一个高饱和主视觉区域，其余区域以白色和浅灰为主。

### 8.2 行情页

- 顶部一级 Tab 与搜索入口保持紧凑。
- 表头和数据列必须对齐；价格、涨跌幅右对齐。
- 涨跌色遵循金融语义 Token，并配合正负号。
- K 线、交易记录等高密度区域减少装饰，保证数据优先。

### 8.3 AI 页面

- 延续 Hufu 蓝色系统，可加入更柔和的青蓝渐变作为 AI 识别层。
- Agent 卡片与普通功能卡片保持相同圆角和间距，不另起一套视觉语言。
- 用户消息与 AI 消息必须有清晰的角色区分、头像和时间 / 状态反馈。
- 生成中、失败、重新生成、复制、点赞等状态必须完整。

### 8.4 我的与设置页

- 使用 `groupedBackground` 页面底色和白色列表分组。
- 分组间距 `16–24px`，组内行高 `48–56px`。
- 页面不使用重卡片投影，依靠白色表面和背景差建立层级。
- 版本、开关状态、币种单位等辅助信息右对齐并使用次级颜色。

### 8.5 转账、授权与签名页

- 金额是第一视觉焦点，网络和币种必须始终可见。
- 地址、合约、Gas、Nonce 等信息分组展示，长内容支持复制和展开。
- 主 CTA 固定在底部时必须避让键盘与系统安全区。
- 风险提示使用警告色浅底，不用整页红色制造恐慌。
- 确认按钮文案必须描述动作，禁止只写“确定”。

## 9. 图标、图片与品牌素材

- 优先复用项目现有 `iconfont`、Hufu 资源图标和链官方图标。
- 同一操作域保持统一的图标线宽和视觉尺寸。
- 常规图标基准 `24px`，辅助图标 `16–20px`，快捷入口图标 `32–40px`。
- 禁止使用 Emoji 充当界面图标。
- 链 Logo、代币 Logo 保持原始比例，不拉伸、不随意变色。
- 网络图片必须提供占位图、加载态和失败态。
- Hufu 品牌图形可用于启动、关于、品牌空状态；不要在普通列表中重复堆叠。

## 10. 动效与反馈

- 点击反馈：`100–150ms` 透明度或颜色变化。
- 页面和面板切换：`180–250ms`。
- 加载与状态过渡：不超过 `300ms`，持续加载动画除外。
- 优先使用 `opacity` 与 `transform`，避免动画宽高导致布局抖动。
- 资产金额刷新不得闪烁；保留旧值至新值成功返回。
- 支持减少动态效果设置；减少动态时关闭大范围位移和循环装饰动画。
- 所有异步按钮在请求中禁用，并提供加载反馈。

## 11. 可访问性与安全体验

- 正文与背景对比度至少 `4.5:1`，大字至少 `3:1`。
- 图标按钮提供语义名称；Flutter 使用 `Semantics`，HTML 使用 `aria-label`。
- 不以颜色作为唯一状态表达。
- 支持系统字体缩放，关键按钮和金额不得被截断。
- TalkBack / VoiceOver 的读取顺序应与视觉顺序一致。
- 私钥、助记词、Keystore 等敏感信息默认遮挡，并提供风险提醒。
- 交易不可逆操作必须二次确认，危险按钮与普通主按钮保持明显区分。
- 截图、复制和生物识别状态需要给用户明确反馈。

## 12. HTML 设计稿画布规则

当前平台标记为 `mobile`。HTML 设计稿必须使用固定宽度画布，禁止把画布宽度写成 `100%`。

```css
:root {
  --canvas-w: 420px;
  --canvas-inset: max(0px, calc((100% - var(--canvas-w)) / 2));
}

#app-frame {
  width: 100%;
  max-width: var(--canvas-w);
  min-height: 100dvh;
  margin: 0 auto;
}

.canvas-fixed {
  position: fixed;
  left: var(--canvas-inset);
  right: var(--canvas-inset);
  width: auto;
  transform: none;
}
```

强制规则：

1. Flutter 设计基准保持 `390 × 844`，HTML 预览画框固定为 `420px`。
2. 窄视口下 `--canvas-inset` 自动归零；PC 宽屏下画布居中，不拉伸铺满。
3. AppBar 使用 `sticky` 并位于 `#app-frame` 内。
4. 底部导航、底部按钮、遮罩和 FAB 必须使用画布 inset。
5. FAB 右侧定位使用 `right: calc(var(--canvas-inset) + 16px)`。
6. 底部固定区域增加 `env(safe-area-inset-bottom)`。
7. 页面内容预留 AppBar、底部导航和键盘空间，不允许被固定元素遮挡。
