# HuFu 移动端交互原型 v1

本原型依据 `docs/current-version.md`、`docs/ui-redesign.md` 和 `DESIGN.md` 制作，使用原生 HTML、CSS 和 JavaScript，无运行时依赖。

本版本使用的字体、图片和图标统一放在当前目录的 `assets/` 中，不依赖仓库根目录的公共资源。

## 文档同步基线

- `docs/current-version.md`：用于确认现有产品能力，不要求在改版原型中逐页复刻现有界面。
- `docs/ui-redesign.md`：作为新版信息架构、页面模块、关键流程和安全边界的功能依据。
- `DESIGN.md`：作为移动端画布、组件状态与安全体验的设计约束。
- 原型中的演示数据、网络和 DApp 可以选取代表性样例，但不能改变上述文档定义的产品规则。

当前原型按 `docs/ui-redesign.md` 保留社交页“最近访问 DApp”模块。`UI&UX/v1/README.md` 中“不展示通用最近访问 DApp”的描述与当前功能依据不一致，在产品口径确认前不作为交互原型规则。

## 原型定位

原型用于说明功能范围和交互逻辑，不作为最终 UI 的排版依据。后续原型页面可以通过连线、编号和便签补充以下信息：

- 点击入口与目标页面
- 弹层、返回和中断规则
- 加载、空数据、失败、禁用与完成状态
- 网络、账户和钱包上下文变化
- 签名、授权、跨链及资产操作的安全确认点

正式视觉方案位于 `../../UI&UX/v1/`，只继承原型的功能目标和约束，页面布局与视觉表现独立设计。

## 具体原型页面

### 市场

- 入口：底部导航 `市场` Tab。
- 页面顶部展示当前公开市场数据标题，不重复显示当前钱包信息；切换网络或账户后，行情上下文同步更新。
- 第一层提供行情分类筛选：全部、FullOn、Bitcoin、Ethereum、Solana、BSC、Tron；默认展示全部。
- 首屏保留 FLON/USDT 重点行情大卡：展示交易对、当前价格、今日涨跌幅、实时标识、简化走势图和前往 FullSwap 入口。
- 行情列表展示币种图标/字母标识、名称、所属网络、交易对、当前价格、涨跌幅和迷你走势图；列表按市场数据排序，不按用户持仓排序。
- 点击任意行情进入详情页：展示交易对、价格、今日涨跌、24h 最高/最低/成交量、近期成交记录，并提供前往 FullSwap 的入口。
- 详情页底部明确标注“行情仅供参考，不构成投资建议”；HuFu 不在行情页面内直接提供交易撮合或资产托管服务。
- 市场 Tab 同时展示市场快讯：标题为“保持知情”，支持查看更多；快讯点击后展开详情或提示，不作为直接交易入口。
- 加载失败时保留本地钱包功能，单独提示行情与快讯模块失败，并提供重新加载入口。
- 筛选无结果时展示空状态和重置筛选入口。

### 首页无钱包状态

- 入口：`首页 → 当前钱包 → 首页演示状态 → 无钱包`
- 页面提供“创建钱包”“导入钱包”“通过 RWID 恢复”三个入口。
- 三类入口统一进入三步安全流程：选择方式、安全确认、模拟完成。
- 创建流程说明本地生成密钥、设置设备内唯一昵称和可选 RWID 绑定。
- 导入流程不请求真实助记词或私钥，只说明安全输入边界。
- RWID 流程展示新设备生成新密钥、手机号验证、公钥换绑、限频、异常设备、冷静期和旧设备通知。
- 完成后返回已有钱包首页状态。

### 钱包详情

- 入口：`我的 → 当前钱包卡 → 钱包详情`，也可以从资产预览的“全部”进入。
- 页面展示当前网络、本地昵称、链上账户名、缩略地址和总资产估值。
- 转账、收款、记录和扫一扫直接复用首页既有交互面板。
- 页面展示代币/NFT、添加代币入口和当前钱包完整资产列表。
- 切换钱包后，钱包详情和首页使用同一钱包上下文。

### FullBridge 状态页

- 入口：`首页海报或推荐 DApp → FullBridge → 核对并模拟跨链`。
- 状态页提供“正常”“失败”“超时”“不支持”四种演示状态。
- 失败状态提示资产仍在源链并提供重试、链上记录和返回修改入口。
- 超时状态提示不要重复提交，并保留链上追踪入口。
- 不支持状态提示修改资产或目标网络。

### Aime 到 DApp

- 入口：`Aime → FullSwap 是什么？ → 查看 FullSwap 访问确认`。
- Aime 回答只提供说明和访问入口，不自动打开、连接或授权。
- 访问确认页继续核对官方域名、所需网络、当前钱包和风险。

### 发现筛选

- 入口：`发现`。
- 第一层按 FullOn、Bitcoin、Ethereum、Solana、BSC 和 Tron 网络筛选。
- 第二层按交易、跨链、红包、借贷与质押和 RWA 类型筛选。
- 网络与类型组合无结果时展示空状态和“重置筛选”入口。
- 演示应用明确区分已核验官方应用和代表性样例。

### DApp 访问确认

- 入口：首页、社交、市场、发现或 Aime 中的 DApp 入口。
- 页面展示 DApp 名称、官方域名、所需网络、当前钱包和即将执行的动作。
- FullSwap 明确显示“交易执行方：FullSwap 智能合约”。
- 当前网络不匹配时先解释切换原因，再由用户确认。

## 原型验收规则

- 五个一级 Tab 的页面状态和当前钱包上下文保持一致。
- 切换网络或账户后，资产、行情、DApp 和后续签名上下文同步更新。
- 首页和钱包详情的快捷功能保持同源，不出现两套不同流程。
- DApp 打开前必须展示名称、目标域名、当前网络、所需网络和风险提示。
- 转账、授权、兑换和跨链确认必须展示执行方、网络、账户、资产、费用及风险。
- 扫码只负责解析和预填，不能自动连接、授权、签名或发送交易。
- 从 DApp 或操作流程返回时，保留原 Tab、会话、行情或推荐上下文。
- 行情和持仓排序只用于信息展示，不构成投资建议。
- 原型未覆盖的目标流程必须保留在“待补齐流程”，完成后再移入“已覆盖流程”。

## 原型边界

- 所有行情、余额、地址和交易记录均为演示数据
- 不连接真实钱包、DApp 或网络接口
- 不请求助记词、私钥、短信验证码或真实签名
- 转账、授权和跨链只演示信息核对，不提交链上交易
